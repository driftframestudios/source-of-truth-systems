# Publication boundary

## Contract

- **What:** A bounded credential-shaped material observation, alongside a distinct reading of embedded metadata and publication intent.
- **When:** Source, an exact proposed index, documentation or an archive is preparing for another repository, release or public audience.
- **Boundaries:** User authorization supplies publication and mutation authority. This method identifies candidates; the credential owner determines validity and any rotation. Scanning keeps provider validation disabled. Repository visibility, rights, consent and historical cleanup retain their existing owners.
- **Result:** The selected detector path proves detection and masking, each named scope returns zero unresolved matches or a private recovery route, and the receipt states its coverage.

## Rules

### Rule: The receiving source owns its observation

Read the local [runbook](../../../docs/runbooks/publication-scan.md), pinned [installer](../../../scripts/security/install-betterleaks.mjs), [scanner](../../../scripts/security/scan-secret-material.mjs) and [configuration](../../../.betterleaks.toml). Another repository's receipt supplies lineage. The assembled receiving source supplies its own observation. Commands work without another checkout or private account.

### Rule: Every invocation proves the detector first

The scanner generates a new non-issued provider-shaped value in memory and requires its finding exit, parsed masked report and sanitized return. A failed canary stops acceptance of a subsequent clean result. Installation verifies the official archive checksum and records executable identity; each scan verifies that receipt, current executable bytes and reported version.

### Rule: Scope determines the claim

Tracked working files, exact index blobs, a committed export, a changed-commit comparison, local-ref textual history and a named artifact are separate scopes. A changed-source pass leaves unchanged files and earlier history unobserved. A quiet or skipped CI job records selection, not inspected behavior. Source and configuration changes reopen their affected observations.

### Rule: Findings remain private until classified

Normal output carries scope, count, rule and safe identity. Candidate values, raw diagnostics, paths, headers, filenames and commit messages stay outside published logs and receipts. A plausible credential pauses the affected handoff and routes to its owner; rotation precedes cleanup. A verified non-issued fixture earns one exact path/rule/value exception and an executable boundary check. Broad baselines and inline allowances do not substitute for classification.

### Rule: Metadata and audience need their own reading

Inspect publication images for EXIF/XMP/IPTC location, device serial, author, capture time, workstation path and tool residue. Inspect archive entries and generated derivatives, preserving intentional color profiles and attribution. A credential scan does not establish metadata absence, visible-content suitability, rights or consent. Current binary metadata and historical binary objects are different observations.

## Sequence and completion

1. Confirm source revision, existing changes, intended receiving event and authority. Preserve unrelated work.
2. Select the smallest scope that can change the decision; use the runbook's deeper release route when a complete snapshot leaves the repository.
3. Verify the installer and configuration, run the fresh-canary scope, and read its sanitized outcome.
4. Classify candidates privately or receive the clean bounded result. Inspect relevant binary metadata separately.
5. Return one receiving record with source/configuration identity, executed scope, outcome, limitation and next receiver. Re-run after assembly in another repository.

Completion means every requested scope has a clean receipt or named private response owner. It grants neither publication approval nor universal secret absence. Re-enter when the source, engine, exceptions, artifact generator, audience or receiving assembly changes.

This method adapts the public [exemplars secret-boundary contract](https://github.com/driftframestudios/human-ai-systems-exemplars/blob/main/.agents/skills/secret-boundary-inspection/SKILL.md). The local implementation and tests are the operative owners.
