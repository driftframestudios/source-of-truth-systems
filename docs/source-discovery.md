# Sources, saved metadata and local search

Sources keeps its type filters, source cards and selected record usable together at desktop and compact laptop widths. A search appears beside the records it actually filters. This contract records the resulting collection, selection and edit behavior.

## Sources composition

The left column uses a bounded 260–340px width. Search, wrapping type buttons and the result count retain their height; the source list receives the remaining scrollable space. The right record has a separate vertical scroll area, a bounded reading width and wrapping relationship descriptions. The two authority groups retain their paired presentation. The shared appearance roles supply surfaces, text, focus and confidence accents.

The workspace grid explicitly bounds both its columns and row. Its Radix viewport retains scrolling; a Sources-only rule replaces Radix's internal table measurement wrapper with a wrapping block. This prevents content width and height from forcing the inspector beyond its receiving viewport. The shared ScrollArea component and other consumers keep their existing behavior.

Selecting a card opens that exact source; selecting it again closes the detail. Filtering changes the list while leaving an already inspected source available. A direct Corridor reference clears the local query and type filter, selects the exact source and retains the existing return route. The count names the filtered and total records; an empty result explains how to recover.

Edit metadata opens a compact form in the selected source. Display title, summary and tags use the current Source command owner, with permission and expected revision checked at acceptance. With the additive workspace schema installed, an explicit first save starts a disposable visitor workspace and saves those fields through GraphQL. The compact status strip names saved/local/unavailable state, expiry and reset; a small disclosure shows that source's saved edits. Source IDs, authority scopes, role, status, confidence and source-update date retain their bundled provenance. The list, local search, relationships and mobile exact-source receiver read the accepted projection. Cancel retains the accepted record; a refused save keeps the draft visible. The selected source, registry filters and unfinished metadata draft survive section return, Back/Forward and responsive layout changes. [Shareable navigation](shareable-navigation.md) describes the in-memory draft owner, cancellation and workspace namespace boundaries.

Restore bundled source reads that one source's canonical metadata and reports whether anything changed. It uses the same local or hosted command route as Save. This recovery is a guarded metadata edit, not an external connector refresh or a freshness timestamp. A valid workspace cookie restores saved Source metadata after reload; other local workflow owners retain their existing session lifetime. Reset workspace revokes only that browser's saved Source overrides. It is distinct from Access Grid's Reset scenario grants.

`services/sourceEditor.ts` owns app-session draft text and editor generations separately from accepted records. `services/sourceSession.ts` owns validated field limits, immutable source revisions and command-time permission checks. `sourceWorkspace.ts` owns hydration, in-flight commands, exact retry identity and workspace generations; `workspaceTransport.ts` owns finite operation identities and the same-origin request. `sourceSessionContext.tsx` binds these to the existing lazy app-instance resource; `useSourceRecords` supplies accepted records to read-only receivers. Hydration precedes a hosted write. Late responses cannot replace a newer revision or another workspace. A stale form preserves its draft and the current accepted record. Public synthetic source references use the workspace-edit capability with an owner-resolved ID; their source-authority matrix remains separate from user-access grants.

The explicit `LOCAL` response preserves browser-session editing before workspace installation, and the Vite source-development mode remains intentionally local. A network failure or installed-database outage keeps the hosted draft pending instead of reporting local success. Expiry offers a new disposable workspace. [The workspace contract](visitor-workspaces.md) describes cookie ownership, limits, migration and recovery.

The Pipeline configuration manifest is documentary Source metadata. Its form edits title, summary and tags; it does not parse or execute YAML. React renders accepted text as text. [The input-boundary assessment](research/input-boundaries.md) records this distinction from HTML sanitation and executable configuration.

`components/SearchField.tsx` provides the controlled input, explicit clear action and focus treatment for Sources, Corridor and Error Lab. Each receiving view owns what matches and how its results appear. `services/search.tsx` retains the Corridor query used by the desktop return route and the small deterministic matcher; it is not a global result index.

## Future discovery boundary

A useful global search would project typed entries from the canonical record owners: stable ID, human title, record kind, searchable text and an exact navigation target. For this example's small collections, deterministic in-memory matching and grouped results are sufficient. Exact IDs and title matches can lead the result order; the existing record resolver can open a supported destination and preserve return context. Permission-aware result visibility belongs with the access foundation, before a global index exposes records from multiple domains.

AI-assisted questions are a separate explicit operation. A future implementation can receive the same authorized source projection and return source-linked answers while keeping ordinary find/filter actions deterministic. Current-view search creates no inference request, external source fetch or new persistence boundary. Accepted metadata preserves source identity and relationships. A future remote refresh requires a named connector and an observed response before it can report new source content.

Settled captures compare the Sources family before and after the repair. These checks establish the named records and viewports in the local production build; operator upload remains the hosted receiving check.
